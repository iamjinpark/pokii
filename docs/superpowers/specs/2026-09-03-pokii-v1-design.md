# pokii v1 설계

작성일 2026-09-03 · 상태: 검토 대기

목표를 정하고 매일 하나씩 포도알을 채워 포도송이를 완성하는 셀프 보상 앱.
첫 출시는 Google Play(Android), iOS는 후속.

이 문서의 범위는 **데이터·도메인은 v1 전체, UI는 포도송이 화면 중심**이다.
UI를 v1 전체로 확장하지 않은 이유는 React Native 경험이 없는 상태에서 화면 전체를
설계하면 구현 단계에서 상당 부분이 버려지기 때문이다.

---

## 1. 전제된 기술 결정

| 영역 | 선택 |
|---|---|
| 앱 | Expo (React Native) + expo-router + TypeScript |
| 폴더 구조 | Expo 공식 구조 (`src/app` 라우트 전용, `screens/` · `hooks/` · `utils/`, 테스트 콜로케이트) |
| 서버 상태 | TanStack Query |
| UI 상태 | React 로컬 상태. 전역 상태 라이브러리 없음 |
| 백엔드 | Supabase (Postgres + Auth + RLS) |
| 인증 | OAuth2 전용 — v1은 Google, Kakao |
| 애니메이션 | react-native-reanimated |
| 알림 | expo-notifications (로컬) |
| 빌드·배포 | EAS Build / EAS Submit |
| 다국어 | `expo-localization` + 키-값 파일. **English · 한국어** |
| 로컬 저장 | AsyncStorage (언어 선택 등 기기별 설정) |
| 표시 이름 | **POKII** |
| 패키지명 (`applicationId`) | **`com.pokii.app`** |

`applicationId`는 출시 후 변경할 수 없다. 바꾸면 Play Store에서 다른 앱이 되고
기존 설치자가 업데이트를 받지 못한다. 표시 이름은 언제든 바꿀 수 있다.

규칙 강제는 **하이브리드**로 간다. 깨지면 복구가 어려운 것만 DB가 지키고,
자주 바뀌는 표시 규칙은 클라이언트가 담당한다.

## 2. v1 범위

**포함** — Google/Kakao 로그인, 목표 생성·수정·삭제(최대 3개 동시 진행),
포도송이 화면과 채우기, 하루 소급 보충, 송이 완성/종료 처리, 로컬 리마인더 알림,
보관함(Archive), 설정(알림 시각·로그아웃), **포도알별 기분·메모**, **수확 용기 등급**, **다국어(영어·한국어)**

**제외** 항목에 더해, 다음은 결제 기능과 함께 다음 버전으로 미룬다.
- **mood 색 팔레트 선택.** v1은 기본 팔레트 하나만 쓴다.
  포도 품종을 파는 안은 폐기했다 — 기분이 색을 쓰므로 품종이 쓸 색이 없다.
  대신 **기분 색 조합을 파는 것**이 자연스럽다. 매일 보는 화면이라 결제 동기도 더 크다.
- 목표 개수 확장

**제외** — 결제(인앱 구매), 통계·기록 화면, 다크모드, 위젯, 소셜 공유, 목표 공유,
오프라인 지원, iOS 출시, Apple 로그인

목표 개수 제한(3개)은 v1부터 넣는다. 나중에 제한을 도입하면 기존 사용자가 반발하지만,
처음부터 있으면 자연스럽다. 결제로 해제하는 기능은 다음 버전에서 붙인다.

## 3. 도메인 규칙

```
목표(goal) ─< 송이(bunch) ─< 포도알(grape)
```

### 3.1 송이

- 한 송이는 **10알**이고, 시작일부터 **연속 10일**에 고정 대응한다.
- 칸은 날짜다. 놓친 날은 그 칸이 영구히 빈다.
- 알은 **위에서 아래로** 채워진다. 위치가 곧 날짜 순서이므로 날짜 라벨을 붙이지 않는다.

### 3.2 날짜 경계

`하루`는 **기기 로컬 자정**에 바뀐다. Postgres의 `now()`는 서버 시각이라 사용자의
"오늘"을 알 수 없으므로, **클라이언트가 로컬 날짜를 계산해 서버에 전달한다.**

기기 시계를 조작해 과거 알을 채우는 것은 막을 수 없다. 셀프 보상 앱이라
속일 동기가 없으므로 이 위험은 감수한다.

### 3.3 송이의 수명

```
started_on          1일차
started_on + 9      10일차 (마지막 칸)
started_on + 10     유예일 — 10일차 칸을 소급 보충할 수 있는 마지막 날
started_on + 11 ~   종료
```

유예일이 없으면 10일차 놓침만 유일하게 구제받지 못한다.

### 3.4 포도알

- 목표당 **하루에 하나**.
- 소급 보충은 **어제 하루까지만** 가능하다. 소급 범위가 하루뿐이므로 날짜를
  고르는 UI가 필요 없고, 버튼 하나로 처리한다.
- 미래 날짜는 채울 수 없다.

### 3.5 완성과 종료

- 10알을 모두 채우면 **즉시** 완성 화면.
- 다 못 채운 채로 유예일이 지나면 종료 화면. 통과선은 없다 — 9알이든 3알이든
  기록으로 남기고 동일하게 선택지를 준다.
- 두 경우 모두 **"끝내기 / 한 송이 더"** 를 고른다.
  - *끝내기* → 목표를 보관 처리(`archived_at`)
  - *한 송이 더* → **누른 그날**을 시작일로 새 송이 생성. 이전 송이 종료 다음날이
    아니다. 며칠 뒤에 열었는데 이미 놓친 상태로 시작되면 이상하기 때문이다.

### 3.6 목표

- 동시 진행은 **최대 3개**. 나무에 걸 자리가 3개라는 디자인 제약과 일치한다.
- 목표를 지우면 그 아래 송이와 포도알도 함께 사라진다.
- 목표를 만들면 **1번 송이가 그날 시작일로 함께 생성된다.** 송이 없는 목표는 존재하지 않는다.
- **보관한 목표는 되살릴 수 있다.** Archive에서 다시 나무로 꺼내면 이어서 진행한다.
  - 빈 가지가 있어야 가능하다. 셋이 다 차 있으면 되살릴 수 없다
  - 비어 있는 자리 중 **가장 낮은 번호**에 배정한다
  - `archived_at`을 null로 되돌리고, **되살린 그날을 시작일로 새 송이를 만든다.**
    `sequence`는 이어진다(No.3까지 있었으면 No.4)
  - 같은 목표를 새로 만드는 것과 달리 **예전 기록이 그대로 이어진다**
- 진행 중인 목표를 중간에 그만두는 기능은 없다. 잘못 만든 목표는 **삭제**하고(송이·알 함께
  사라짐), 하기 싫어진 목표는 열흘 뒤 종료 시점에 "끝내기"를 고르면 된다. 종료 경로를
  하나로 유지하기 위해서다.

### 3.7 알림

로컬 알림만 쓴다. 서버 푸시는 v1에 없다.

- **하루 두 번** — 낮에 한 번, 밤에 한 번. 기본값은 `13:00`과 `22:00`이다.
- **아직 오늘 알을 채우지 않은 목표가 있을 때만** 알린다. 다 채운 날은 둘 다 울리지 않는다.
- 목표별로 따로 울리지 않는다. 목표가 세 개여도 알림은 한 번에 하나다.
- 두 시각 모두 사용자가 바꿀 수 있고, 각각 끌 수 있다.
- 권한을 거부해도 앱의 나머지 기능은 정상 동작해야 한다.
- 알림 예약은 기기 로컬 시각 기준이며, 날짜 경계(§3.2)와 같은 기준을 쓴다.



### 3.8 기분과 메모

포도알 하나는 **하루의 기록**이다. 알을 채우는 행위 자체가 그날의 기분을 고르는 것이다.

- 기분은 **다섯 가지 범주**다 — `excited` · `happy` · `calm` · `tired` · `sad`.
  좋고 나쁨의 척도가 아니라 감정의 종류이므로 숫자로 저장하지 않는다(§4 참고).
- **기분은 필수다.** 기분이 곧 포도알의 색이므로 기분 없이는 알을 그릴 수 없다.
- 메모는 **100자 이내이며 선택 사항**이다.
- **기록에는 기한이 없다.** 몇 달 전 완료된 송이의 기분·메모도 언제든 읽고 고칠 수 있다.
  소급 보충 1일 제한은 포도알을 *채우는* 규칙이지 기록에는 적용되지 않는다.

**하루 기록 화면 하나가 채우기와 수정을 모두 담당한다.** 진입점은 셋이다.

| 진입점 | 모드 |
|---|---|
| 오늘·어제의 빈 알 탭 | 채우기 |
| 채워진 알 탭 | 수정 |
| 열흘 기록의 줄 탭 | 수정 |

이 기능이 앱의 성격을 바꾼다. 습관 트래커 위에 기록이 얹혀서, 송이 하나가
"열흘간의 기록"이 된다. 완성한 송이를 나중에 다시 읽는 것이 이 기능의 목적이므로
Archive에서도 읽을 수 있어야 한다.

### 3.9 수확과 용기 등급

`finish` 또는 `one more`를 고르면 송이가 **수확**되어 용기에 담긴다.

| 채운 개수 | 용기 |
|---|---|
| 10 | 바구니 — 손잡이·리본이 달린 것 |
| 3 ~ 9 | 나무 상자 |
| 3 미만 | 소쿠리 |

- **등급은 송이마다 계산된다.** 10일 = 수확 한 번 = 용기 하나이므로 시간 단위가 명확하다.
- 저장하지 않고 `grapes` 개수로 계산한다. `containerFor(filledCount)` 순수 함수 하나면 된다.
- Archive의 목표 카드에는 **가장 최근 송이의 용기**를 대표로 보여준다.

목표 단위로 평균을 내지 않는다. 10/10을 해낸 열흘이 평균에 묻히고, 목표를 오래 끌수록
등급이 내려가기 때문이다.

용기는 **담는 것**으로 통일한다. 잼·주스처럼 가공물로 가는 안은 검토 후 폐기했다 —
포도알이 사라지면 §3.8의 기록도 그림에서 함께 사라진다.

## 4. 데이터 모델

```sql
goals
  id          uuid pk
  user_id     uuid not null → auth.users
  title       text not null            -- 긴 제목. 상세 화면에 표시
  tag         text not null            -- 짧은 이름. 나무의 태그에 표시 (8자)
  position    smallint not null        -- 나무의 자리 1·2·3
  created_at  timestamptz not null default now()
  archived_at timestamptz              -- "끝내기" 선택 시
  unique (user_id, position) where archived_at is null

bunches
  id          uuid pk
  goal_id     uuid not null → goals (on delete cascade)
  user_id     uuid not null            -- RLS용 비정규화
  sequence    int  not null            -- 화면의 No.1, No.2
  started_on  date not null            -- 화면의 Start.YYMMDD
  closed_at   timestamptz              -- 결과 화면을 확인한 시각
  unique (goal_id, sequence)
  unique (id, goal_id)                 -- grapes의 복합 FK 대상

grapes
  id          uuid pk
  bunch_id    uuid not null
  goal_id     uuid not null            -- 유니크 제약용 비정규화
  user_id     uuid not null            -- RLS용 비정규화
  grape_date  date not null            -- 이 알이 속한 날짜
  filled_at   timestamptz not null default now()   -- 실제로 채운 시각
  mood        text not null            -- excited|happy|calm|tired|sad
  note        text                     -- 100자 이내. null 허용
  check (mood in ('excited','happy','calm','tired','sad'))
  unique (goal_id, grape_date)
  foreign key (bunch_id, goal_id) → bunches (id, goal_id) on delete cascade
```

### 설계 근거

**`title`과 `tag`를 분리한 이유** — 나무에는 송이가 셋 걸리는데 자리가 좁아 긴 제목을 넣으면
`Build this pro…`처럼 잘려 구분이 되지 않는다. 사용자가 짧은 이름을 직접 짓게 하면 잘릴 일이 없고,
자기 언어로 지은 것이라 식별력도 높다.

**`position`을 저장하는 이유** — 나무의 세 자리가 고정이고 목표가 만들어진 순서대로 배정된다.
가운데(1번)가 첫 목표, 위(2번)가 두 번째, 아래(3번)가 세 번째다. 보관하지 않은 목표끼리
자리가 겹치지 않아야 하므로 부분 유니크 제약을 건다.

**`grape_date`와 `filled_at`을 분리한 이유** — 소급 보충 때문이다. 어제 것을 오늘
채우면 두 값이 달라진다. 이 구분이 없으면 소급 기능 자체가 성립하지 않는다.

**`mood`를 숫자가 아니라 텍스트로 두는 이유** — 다섯 가지는 좋음-나쁨 척도가 아니라
감정의 범주다. `calm`이 `happy`보다 낮은 것이 아니고 `tired`와 `sad`는 방향이 다르다.
숫자로 저장하면 "평균 기분 3.2" 같은 무의미한 계산을 하게 되고, 나중에 감정을 추가하거나
순서를 바꿀 때 기존 데이터의 뜻이 바뀐다.

**`mood`는 null을 허용하지 않는다** — 기분이 곧 알의 색이라 색 없는 알은 그릴 수 없다.
`note`만 선택 사항이다.

**놓친 날은 행을 만들지 않는다.** 빈 칸 = 해당 날짜의 행 없음. 화면은
`started_on ~ +9`의 열 개 날짜를 만든 뒤 각 날짜에 행이 있는지로 상태를 결정한다.

**`unique (goal_id, grape_date)`가 이 스키마에서 가장 중요한 제약이다.** 버튼 연타,
네트워크 재시도, 두 기기 동시 조작 — 어떤 경로로도 하루에 두 알이 들어가지 못한다.
클라이언트 로직만으로는 완전히 막을 수 없는 종류의 문제다. `bunch_id`가 아니라
`goal_id` 기준인 것은 목표 단위로 "하루 한 알"을 보장하기 위해서다.

**복합 외래키가 필요한 이유** — `grapes`가 `bunch_id`와 `goal_id`를 모두 들고 있어
둘이 어긋날 수 있다. A목표의 포도알이 B목표의 송이를 가리키면 화면이 조용히 망가지고
원인 추적이 어렵다. `bunches`에 `unique (id, goal_id)`를 두고 복합 FK로 참조하면
불일치가 **입력 단계에서 불가능**해진다.

### 인덱스

유니크 제약이 인덱스를 겸한다. 추가로 필요한 것은 `goals(user_id)` 하나뿐이다.

## 5. 보안

### 5.1 역할 분담

| DB가 지킨다 | 클라이언트가 지킨다 |
|---|---|
| 소유권 (RLS) | 소급 보충 1일 한도 |
| 하루 한 알 | `grape_date`의 송이 범위 |
| 송이 번호 중복 | 미래 날짜 차단 |
| 참조 무결성 | 목표 3개 제한 *(주의: 아래 참고)* |

### 5.2 `user_id`는 서버가 채운다

클라이언트가 보내는 `user_id`를 믿으면 안 된다. `BEFORE INSERT` 트리거에서
`auth.uid()`로 덮어쓴다. 클라이언트는 이 값을 아예 보내지 않는다.

### 5.3 목표 소유권 확인

`user_id`만 검사하면 **내 `user_id` + 남의 `goal_id`** 조합이 통과한다.
`grapes`의 insert 정책에서 목표 소유권까지 확인한다.

```sql
create policy grapes_insert on grapes for insert
  with check (
    exists (select 1 from goals g
            where g.id = goal_id and g.user_id = auth.uid())
  );
```

`select`·`update`·`delete`는 `user_id = auth.uid()`로 충분하다.

### 5.4 목표 3개 제한에 대한 주의

v1에서는 클라이언트가 막는다. 결제로 제한을 해제하는 기능이 붙는 순간
**이 검사는 반드시 서버로 옮겨야 한다.** 돈이 걸린 규칙을 클라이언트가 지키면
앱을 수정해 우회할 수 있다. 결제 도입 시 `entitlements` 테이블과 서버 측
개수 검사를 함께 추가한다.

### 5.5 마이그레이션

Supabase CLI로 관리하고 `supabase/migrations/*.sql`을 저장소에 커밋한다.
대시보드에서 직접 수정하지 않는다 — 로컬과 원격이 갈라지면 어느 쪽이 정본인지
알 수 없게 된다.

파일명은 kebab-case를 쓴다 (2026년 1월부터 Expo 공식 권장).

### 6.1 날짜·송이 규칙을 순수하게 유지하는 이유

10일 경계, 유예일, 소급 판정, 칸 상태 계산은 전부 `utils/date.ts`와 `utils/bunch.ts`에 들어간다.
Supabase도 React Native도 참조하지 않으므로 **에뮬레이터 없이, 로그인 없이
테스트할 수 있다.** 규칙이 컴포넌트 안에 섞이면 이게 불가능해진다.

```ts
canFillDate({ startedOn: '2026-09-01', today: '2026-09-12', target: '2026-09-10' })
```

### 6.2 TanStack Query

```
['goals']                          나무 화면 — 목표와 각 목표의 현재 송이
['goal', goalId, 'currentBunch']   상세 화면 — 송이와 포도알 전부
```

쿼리 단위를 화면 기준으로 잡는다. 칸마다 요청이 나가지 않게 한다.

### 6.3 포도알 채우기

낙관적 업데이트로 처리한다. 탭하면 서버 응답을 기다리지 않고 즉시 채워지고,
실패하면 되돌린다. 하루에 한 번뿐인 핵심 동작이라 여기서 지연이 보이면
앱 전체가 굼떠 보인다.

**유니크 제약 위반은 에러로 다루지 않는다.** 원하던 상태가 이미 달성된 것이므로
조용히 성공으로 처리하고 화면만 맞춘다.

**되돌리기** — 채운 직후 몇 초간 undo 스낵바를 띄운다. 하루 한 알 제약 때문에
실수로 채우면 그날이 소진되므로 취소 경로가 없으면 곤란하다.

### 6.4 오프라인

v1에서 지원하지 않는다. 네트워크가 없으면 안내만 표시한다.
모든 쓰기가 `utils/supabase.ts`를 지나가므로 나중에 큐를 붙일 자리는 열려 있다.

## 7. 화면과 인터랙션

v1 화면은 여덟 개다.

```
Login → Tree ┬ 빈 가지 탭    → Create Goal    → (나무로)
             ├ 진행 중 송이 탭 → Bunch Detail   → 메뉴 → 목표 수정·삭제
             └ 끝난 송이 탭   → Complete / End → (나무로)

하단 탭: tree · archive · settings
```

### 7.1 Tree (메인)

가지가 **세 개**, 자리가 고정이다.

```
   ②
      ①      1번(가운데)이 첫 목표
   ③
```

목표는 만든 순서대로 1 → 2 → 3 자리에 배정되고 순서는 바뀌지 않는다.
첫 목표가 가운데에 오므로 하나만 있어도 화면이 허전하지 않다.

각 가지는 세 상태 중 하나다.

| 가지 상태 | 표시 | 탭하면 |
|---|---|---|
| 빈 가지 | 점선 원 + `+` | Create Goal |
| 진행 중 송이 | 진행도 + 태그 | Bunch Detail |
| 끝난 송이 | 후광 + 반짝임 + 태그 | Complete / End |

**여기서 포도알을 채우지 않는다.** 어제 빈 칸이 있는 송이에는 **빈 pokii 알 모양의 배지**를 붙인다.
텍스트나 느낌표를 쓰지 않고 알 자체로 "채울 것이 남았다"를 말한다.

**목표 태그** — 각 송이 옆에 표본 태그가 끈으로 매달린다. 담는 것은 `goals.tag` 하나뿐이며
진행도나 날짜는 넣지 않는다. 구분이 목적이므로 가장 가벼운 형태를 택했다.

**Tree의 6가지 상태**

1. 목표 0개 — 빈 가지 셋 · `your tree is waiting`
2. 진행 중, 오늘 채울 것 있음 — `let's collect today's pokii`
3. 오늘 다 채움 — `all done for today`
4. 어제 미충족 배지 · 완료 송이 후광이 함께 보이는 상태
5. 가지 3개가 다 참 — 새가 등장
6. 로딩·에러 — 흐린 원으로 자리만 잡고 대기, 실패 시 재시도

### 7.2 새 (마스코트)

**가지 3개가 다 찼을 때** 날아와 말풍선을 띄운다.

```
v1        your tree is full!
          finish a bunch to plant a new one

결제 도입 후  (위에 한 줄 추가)  or grow one more branch →
```

**5초 뒤 말풍선만 사라지고 새는 자리에 남는다.** 상시 공지 아이콘 역할을 하며,
나중에 결제가 붙으면 이 새를 탭하는 흐름으로 자연스럽게 이어진다.

v1에는 결제가 없으므로 새는 **왜 목표를 만들 수 없는지 설명**하는 역할만 한다.
빈 가지가 없으면 사용자는 이유를 알 수 없다.

상시 노출되는 별도의 결제 입구는 v1에 만들지 않는다.

### 7.3 Create Goal

나무의 빈 가지를 탭해 들어온다. 빈 가지가 있을 때만 진입할 수 있으므로
3개 제한이 진입 단계에서 지켜진다.

**입력 두 가지**
- 목표 제목 — 최대 60자
- 짧은 이름(tag) — 최대 8자. **필수**이며 제목의 첫 단어를 자동 제안한다

짧은 이름을 선택 항목으로 두면 비었을 때 제목을 잘라 써야 하고, 그러면 원래 문제로 돌아간다.
필수로 하되 자동 제안으로 마찰을 줄인다.

안내는 한 줄로 둔다 — `starts today · 10 days · 1 pokii a day`

**취소** — ✕ 버튼. 입력 중에 나가려 하면 확인을 묻는다.

**상태 6개**

| 상태 | 동작 |
|---|---|
| 진입 직후 | 버튼 비활성, 플레이스홀더 표시 |
| 입력 중 | 버튼 활성, 글자수 카운터 |
| 글자수 초과 | 입력은 막지 않고 버튼만 잠금, 카운터 강조 |
| 저장 중 | **버튼 잠금**, ✕ 숨김 |
| 저장 실패 | 입력 내용 유지, 재시도 |
| 가지 꽉 참 | 진입 불가. 나무에서 새가 안내 |

**저장 중 버튼 잠금은 기능 요구사항이다.** 두 번 누르면 목표가 두 개 생겨 3개 제한이 뚫린다.
제목이 같아도 서로 다른 목표이므로 스키마의 유니크 제약으로는 막을 수 없다.

목표를 만들면 §3.6대로 1번 송이가 함께 생성되고 나무로 돌아간다.

### 7.4 Bunch Detail

```
No.1                    Start.261021
Build this project and deploy soon
              (송이)
```

- `No.N` = `bunches.sequence`, `Start.YYMMDD` = `bunches.started_on`
- 제목은 `goals.title`(긴 쪽)을 쓴다. 3줄 이상 흐르는 것을 전제로 레이아웃을 잡는다
- 제목 옆 메뉴에서 목표 수정·삭제

**규칙은 하나다 — 알을 탭한다.** 별도의 `catch up` 버튼을 두지 않는다.
탭했을 때의 결과는 알의 상태에 따라 다르다.

| 알 상태 | 탭하면 |
|---|---|
| 오늘 · 어제 (빈 칸) | **하루 기록 화면**이 열린다 (채우기 모드) |
| 채워진 알 | **하루 기록 화면**이 열린다 (수정 모드) |
| 놓침 · 미래 | 아무 일도 일어나지 않는다 |

**채우는 것과 기분을 고르는 것이 한 동작이다.** 기분이 곧 알의 색이므로 색을 고르지 않으면
알을 그릴 수 없다. 그래서 탭하면 바로 채워지지 않고 기록 화면이 열린다.

**undo 스낵바를 두지 않는다.** 전체 화면에서 색을 고르고 저장하는 흐름이라 실수로 채우는
경로가 없다. 잘못 채운 경우는 그 알을 다시 탭해 수정 모드에서 지운다.

**오늘 알의 위치는 날짜에 따라 이동한다.** 1일차는 맨 위 알, 10일차는 맨 아래 알이 강조된다.
고정된 자리가 아니다.

**상태별 화면**

| 상황 | 화면 |
|---|---|
| 오늘 안 채움 | 오늘 알이 떠 있음 |
| 오늘 채움 | 떠오른 알 없음 · `all done for today` |
| 어제 빈 칸 있음 | 어제 알에 점선 · 하단에 `yesterday is still open` |
| 채운 직후 | 알이 튀어오르며 보라로 · undo 스낵바 |
| 유예일 | 오늘 알 없음. 어제 알(=10일차)만 점선 · `last day to catch up` |

**오늘 채운 뒤 내일 알을 미리 강조하지 않는다.** 강조하면 지금 탭할 수 있다고 오해해
눌러보게 되는데 아무 일도 일어나지 않아 오히려 혼란스럽다.

**메뉴** — `edit goal` / `delete goal` 두 항목.
수정에서는 **제목과 태그를 모두** 고칠 수 있다. 태그를 못 고치면 나무에 표시되는 이름을
영영 바꿀 수 없게 된다.

**삭제 확인** — 사라지는 양을 숫자로 보여준다.
`1 bunch and 4 pokii will be gone. this can't be undone.`
포도알이 이 앱에서 사용자가 쌓아 온 자산이므로, 개수를 보여주는 편이 훨씬 신중해진다.

### 7.5 하루 기록 화면

포도알 하나의 기분과 메모를 다루는 전체 화면이다. §3.8의 진입점 셋이 모두 이 화면을 연다.

```
how was your day?          ✕

        ( 알 미리보기 )
           calm

mood   ● ● ● ● ●            ← 보라 명도 5단계, 아래에 이름
diary  [ A little note... ]  ← 선택

           [ save ]
```

- **색을 고르면 위의 알 미리보기가 그 색으로 바뀐다.** 고르기 전에는 `save`가 비활성이다
- 색 아래에 mood 이름을 표시한다. 표정을 쓰지 않으므로 이름이 유일한 문자 단서다
- 수정 모드에서는 기존 값이 채워진 상태로 열리고, **`remove this pokii`** 로 지울 수 있다.
  하루 한 알 제약 덕분에 지우고 다시 채우는 데 문제가 없다

**저장 후 연출** — §8.5.2

### 7.6 Complete / End

**나무에서 끝난 송이를 탭해야 들어온다.** 앱을 열 때 모달로 띄우지 않는다 —
목표가 셋이면 세 송이가 같은 날 끝날 수 있고, 그때 모달이 연달아 뜨면 앱을 연 목적을 가로막는다.

결과를 보여주고 `one more` / `finish` 중 하나를 고르게 한다. 선택하지 않고 나가도
가지에 끝난 송이가 남아 있으므로 상태가 어긋나지 않는다.

3알 미만이면 숫자 대신 격려 문구를 보여준다. `1 of 10`짜리 텅 빈 송이를 그대로 들이밀면
실패를 확대해 되돌려주는 화면이 된다.

**수확 연출** — 선택하면 송이가 나무에서 떨어져 용기에 담긴다(§3.9).
- **저장 성공 후에 연출을 시작한다.** 연출부터 돌리면 저장이 실패했을 때
  화면은 수확했는데 데이터는 그대로인 상태가 생긴다
- 1초 이내, 탭하면 건너뛴다. 목표가 셋이면 생각보다 자주 본다

### 7.7 Archive

**3단 구조다.**

```
목표 목록 → 송이 목록 → 열흘 기록
```

**① 목표 목록** — 보관한 목표들. 각 카드에 **가장 최근 송이의 용기**(§3.9)와
송이 개수·전체 기간을 보여준다. 탭하면 송이 목록으로.

**② 송이 목록** — 그 목표의 송이들을 최근 순으로. 각 줄에 용기 · `N of 10` · 기간.
여기에 **`plant again`** 진입점을 둔다(§3.6). 빈 가지가 없으면 비활성으로 두고 이유를 알린다.

**③ 열흘 기록** — 송이 하나의 열흘을 날짜순 타임라인으로 보여준다.

- 위에 **송이 그림을 작게** 남긴다. 타임라인만 있으면 여느 일기 앱과 다를 게 없는데,
  송이가 있으면 "이 열흘의 모양"이 한눈에 보인다
- 줄마다 `날짜 · 표정 · 메모`. 메모 없이 기분만 있는 날은 표정만 놓는다
- **놓친 날도 줄을 만든다.** 흐리게 `—`로 표시한다. 빼버리면 날짜가 건너뛰어
  "왜 22일 다음이 24일이지" 하고 헷갈린다
- 줄을 탭하면 **하루 기록 시트**가 열려 전체 메모를 읽고 바로 고칠 수 있다

**③은 진행 중인 송이에도 쓴다.** Bunch Detail에서도 열 수 있게 해서, 완성 전에도 열흘을
훑어볼 수 있다. 화면 하나를 두 곳에서 쓰므로 만들 것도 줄어든다.

연속 일수나 히트맵 같은 통계는 v1에 없다. 이 화면이 없으면 `finish`를 고른 사용자에게는
삭제처럼 보이므로, 통계가 아니라 **만든 것에 접근할 수 있는가**의 문제로 다룬다.

### 7.8 Settings

알림은 **두 줄**이다 — 낮(기본 `13:00`)과 밤(기본 `22:00`). 각각 시각을 바꾸고 끌 수 있다.
언어는 **English / 한국어** 중 선택하며 기본은 시스템 언어를 따른다(§9).
그 밖에 로그아웃, 계정 정보.

### 7.9 Login

Google / Kakao. 세션이 남아 있으면 건너뛰고 바로 Tree로 간다.

### 7.10 하단 탭

`tree · archive · settings` 세 개. 디자인 시안의 네 번째 칸은 없앤다.

## 8. 디자인

### 8.1 포도알 상태

**색이 있으면 채운 날, 회색이면 안 채운 날.** 규칙은 이 하나다.

| 상태 | 표현 | 탭 |
|---|---|---|
| 채움 | **기분에 따른 보라 명도** (§8.1.1) | 가능 (수정) |
| 오늘 | 회색 + **떠오르기 + 후광** | 가능 (채우기) |
| 어제 | 회색 + 주황 점선 테두리 | 가능 (채우기) |
| 놓침 (영구) | 회색 + 투명도를 크게 낮춤 | — |
| 미래 | 회색 | — |

**안 채운 알을 보라 계열에서 뺀 이유** — 기분 색을 보라 명도로 쓰면 가장 옅은 `sad`가
기존의 연보라(미래)와 거의 같아진다. 채운 날과 안 채운 날이 구분되지 않으면 송이를 보는
의미가 사라진다. 색이 곧 기분이므로 **기분이 없으면 색도 없는 것**이 자연스럽다.

**어제와 놓침을 반드시 구분해야 한다.** 어제는 아직 채울 수 있고 그 이전은 영영 채울 수 없다.

놓친 알을 시든/갈색 알로 바꾸는 안은 검토 후 **폐기했다.** 셀프 보상 앱에서 "썩었다"는 신호는
자책을 부르고 앱을 열지 않게 만들 위험이 있다.

채우는 순서가 위→아래로 고정이므로 놓친 알이 채워진 알들 사이에 흐리게 끼어 보이고,
"여기를 건너뛰었다"가 바로 읽힌다.

### 8.1.1 기분 색

보라 한 톤에서 **명도만** 조절한다. 진할수록 에너지가 높다.

| 기분 | 임시 색 |
|---|---|
| `excited` | `#33265E` |
| `happy` | `#4E3480` |
| `calm` | `#6D4CA0` |
| `tired` | `#9377BE` |
| `sad` | `#B7A2D6` |

값은 임시이며 Figma에서 조정한다.

**표정은 쓰지 않는다.** 눈·입으로 5종을 구분하는 안은 검토 후 폐기했다.

**알려진 한계** — 명도만 다르면 인접한 두 단계는 거의 같아 보인다. `happy`와 `calm`을
나란히 놓지 않으면 구분되지 않는다. 이는 받아들인다. 알을 탭하면 이름과 메모가 나오므로
정확한 확인이 가능하고, 송이 전체로는 **"진한 날이 많았나 옅은 날이 많았나"** 라는
열흘의 분위기가 남는다. 개별 판별이 목적이 아니다.

색 이름은 하루 기록 화면에서만 문자로 표시한다(§7.5). 송이에서는 색만 남는다.

### 8.2 송이 완료 표시

완료된 송이는 **뒤에 은은한 후광 + 반짝임**으로 표시한다. `DONE` 같은 텍스트 배지는 쓰지 않는다.
진행 중 알림(빈 pokii 알 배지)과 시각 언어가 겹치지 않아야 한다.

글래스모피즘은 검토했으나 채택하지 않았다. RN에서 실시간 블러(`expo-blur`)는
**Android에서 성능 부담이 크다.** 후광+반짝임은 SVG 그라디언트와 Reanimated만으로 처리된다.

### 8.3 목표 태그

참고 이미지는 박물관 표본 태그다. `pokii` 자체가 수집하는 앱이므로 컨셉이 맞는다.

- 형태: 길쭉한 둥근 사각형, 금속 아일렛 + 끈으로 송이 옆에 매달림
- 색: **단색 크림.** 종이 텍스처 이미지는 쓰지 않는다
- 글꼴: **손글씨체.** 한글 손글씨 폰트는 용량이 크므로 서브셋 처리가 필요하다
- 내용: `goals.tag` 하나뿐. 진행도·날짜는 넣지 않는다

### 8.4 수확 용기

| 등급 | 형태 |
|---|---|
| 10 / 10 | **바구니** — 손잡이와 리본이 달린, 가장 공들인 것 |
| 3 ~ 9 | **나무 상자** |
| 3 미만 | **소쿠리** — 얕고 소박한 것 |

셋은 **얼마나 정성껏 담았나**라는 한 축 위에 있다.

바구니와 상자는 그 자체로는 위계가 약하다. 그래서 **10/10 바구니에만 손잡이·리본·반짝임을
얹어** 차이를 만든다. 물건의 종류가 아니라 **정성의 차이**로 등급을 표현하는 것이다.
이것으로도 부족하면 가운데를 손잡이 없는 민바구니로 바꿔 바구니 계열 3단계
(리본 바구니 → 민바구니 → 소쿠리)로 통일할 수 있다.

와인 병은 후보였으나 제외했다. **알코올 묘사는 Google Play 콘텐츠 등급을 올린다.**

### 8.5 애니메이션

| 대상 | 동작 |
|---|---|
| 오늘 알 | 상시 떠 있는 상태 (scale + 그림자) |
| 알 채우기 | 색연필로 칠하듯 색이 번지며 채워짐 → §8.5.2 |
| 태그 | 대롱대롱 흔들림. **화면 진입 시 한 번만** 흔들고 멈춘다 |
| 송이 완료 | 후광 + 반짝임 |
| **완성 연출** | 아래 §8.5.1 |
| 새 | 날아와 앉기 → 말풍선 → 말풍선만 사라짐 |
| 수확 | 송이가 나무에서 떨어져 용기에 담김. 1초 이내 · 탭하면 건너뜀 · 저장 성공 후 시작 |

태그 셋이 계속 흔들리면 산만하므로 진입 시 1회로 제한한다.

#### 8.5.1 완성 연출 (10알 달성)

10번째 알을 채워 송이가 완성되는 순간의 연출이다.

```
마지막 알이 날아와 박힘 → 쾅(충격파) → 태그에 도장 → 짧은 콘페티
```

- **도장은 태그 위에 찍힌다.** 표본 태그와 같은 세계관이라 앱 전체가 하나로 묶인다.
- **도장이 찍힌 태그는 Archive에 그대로 남는다.** 연출이 한 번 보고 끝나지 않고 흔적이 된다.
- 콘페티는 도장 순간에 짧게만 얹는다.
- **전체 2초 이내, 탭하면 건너뛴다.**

새를 축하에 쓰지 않는다. 새는 "가지 꽉 참" 안내에 쓰기로 했으므로, 축하를 겸하면
새가 나타났을 때 좋은 소식인지 아닌지 구분할 수 없게 된다.

#### 8.5.2 매일 저장 연출

하루 기록 화면에서 `save`를 누른 뒤의 흐름이다.

```
색연필로 칠하듯 알이 채워짐 → 짧은 축하 → 화면 닫힘 → 나무의 송이 자리로 알이 들어감
```

- **전부 합쳐 1.5초 안쪽.** 목표가 셋이면 하루에 세 번 본다
- **콘페티는 쓰지 않는다.** 열흘째 완성 연출(§8.5.1)이 콘페티를 쓰므로,
  매일도 콘페티를 띄우면 특별한 날과 평범한 날이 구분되지 않는다
- 축하는 문구 한 줄로 짧게 (`nice, that's today!` 수준)
- 탭하면 건너뛴다

오늘 알이 항상 다른 알 위에 그려지도록 렌더 순서를 계산해야 한다.

### 8.6 색상값

현재 값은 스크린샷에서 눈대중으로 뽑은 근사치다. 구현 전에 Figma에서 정확한 값을 받아
`theme.ts`에 넣는다.

## 9. 다국어

기본 언어는 **기기의 시스템 언어**를 따른다. 지원하지 않는 언어면 English로 떨어진다.
사용자가 Settings에서 바꾸면 그 선택을 AsyncStorage에 저장하고 시스템 언어보다 우선한다.

지원 언어는 **English · 한국어** 두 가지다.

### 9.1 문자열 분리를 v1부터 하는 이유

번역 자체는 문자열 40개 남짓이라 부담이 아니다. 비싼 것은 **나중에 하드코딩된 문자열을
모든 화면에서 뽑아내는 일**이다. 구조를 처음부터 잡으면 하루면 끝나고, 나중에 하면
전 화면을 다시 뒤져야 한다.

### 9.2 폰트

태그에 쓰는 손글씨체가 문제다. **태그는 사용자 입력이라 어떤 글자가 올지 알 수 없으므로
서브셋을 만들 수 없다.** 한글 손글씨 폰트를 통째로 번들하면 앱 용량이 3~8MB 늘어난다.

UI 고정 문구는 쓰는 글자가 정해져 있어 서브셋이 가능하다.

손글씨 태그는 앱 정체성의 일부이므로 **한글 폰트를 번들하는 쪽**을 택한다.
폰트 선정은 디자인 시스템 단계에서 한다.

### 9.3 레이아웃 규칙

한글은 대체로 영어보다 짧아 넘치는 일은 드물고, **여백이 뜨는** 경우가 많다.

- **텍스트 영역에 고정 높이·고정 너비를 주지 않는다.** 아래 요소는 flex로 흐르게 한다
- **태그 글자수는 언어별로 다르게 잡는다** — 영문 8자 / 한글 5자.
  8자 기준으로 만든 자리에 한글 8자가 들어가면 폭이 두 배가 되어 송이를 덮는다
- 버튼은 최소 폭을 주고 가운데 정렬한다 (`plant it` → `심기`처럼 크게 짧아진다)
- 가운뎃점으로 나열한 문구는 한 줄 고정하지 않고 줄바꿈을 허용한다
