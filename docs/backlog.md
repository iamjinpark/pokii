# Backlog

대기실이지 기록보관소가 아니다. 완료 이력은 closed Issue와 git log가 갖고 있다.

- **보류** — 여기 쌓인다. `/decide`의 입력
- **유지 → Issue 생성됨** — 이 파일에서 **삭제한다.** 추적은 Issue가 한다
- **제외** — 한 줄 이유와 함께 남긴다. 같은 논의를 반복하지 않기 위해서다

## 보류

- 떠 있는 면 재질 재검토 — 메뉴·모달·토스트·송이 시트가 유리(흰색 20%, 흐림)인데 "투박한 페이퍼컷" 컨셉과
  결이 다르다는 의견(#60). 불투명 종이·오려 붙인 가장자리·어긋난 종이 그림자 등을 네 요소에 한꺼번에 놓고 비교한 뒤
  정해지면 한 번에 바꾼다. 안드로이드는 흐림이 없어 반투명만 보이는 점도 같이 본다

- 짧은 이름(tag) 입력 유지 여부 — 나무 이름표와 송이 시트에서 모두 빠져 지금은 보이는 곳이 없다(#60).
  목표 만들기·수정에서 계속 받을지 정한다

- 포키 문구 스타일 (추후 설정) — 화면마다 말투가 섞여 있다("~해요"체, 명사형 "목표 삭제", 영어 소문자).
  말투·버튼(짧은 동사)·안내와 경고의 톤·포키 단어(송이·포도알)·영어 규칙을 한 번 정해 앱 전체 문구의 기준으로 삼는다

- 포키 일기예보 — 날씨를 날짜로 정하므로(#58) 내일·모레 날씨를 미리 알 수 있다.
  나무 화면 예보 한 줄이나 새가 물고 오는 편지로 "내일 포키에 비 와요"를 알려 주는 안. 스펙·시안 없음

- 접근성 라벨 다국어화 — `tree-screen.tsx`의 `accessibilityLabel`이 한국어로 하드코딩되어 있다.
  영어 사용자의 스크린리더가 한국어를 읽는다. i18n 키로 옮길 것 (계획 2 UI 작업 때 함께)

- 세션 토큰 암호화 — `AsyncStorage`는 평문이라 루팅된 기기에서 토큰을 읽을 수 있다.
  Supabase 공식 `LargeSecureStore` 패턴(AES 키는 `expo-secure-store`, 암호문은 `AsyncStorage`)으로 해결.
  `expo-secure-store`는 값당 2048바이트 제한이 있어 세션을 통째로 넣지 못하므로 이 우회가 필요하다.
  결제 기능이 붙어 민감도가 올라가는 시점에 적용할 것

- 스크린샷 검증을 로컬 Supabase로 전환 — 현재는 개발자 본인 세션 토큰을
  `.auth/session.json`에 1회 복사해 쓴다(#20). Docker를 설치하면 `supabase start`로
  격리된 로컬 스택에 테스트 유저를 만들어 실제 데이터가 있는 화면을 검증할 수 있다.
  `supabase` CLI는 이미 devDependency에 있고 Docker만 없다.
  실토큰을 로컬 파일에 두지 않아도 되는 이점이 있다
